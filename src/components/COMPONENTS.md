# ReQore Components

| Component | Description |
| --- | --- |
| **ReqoreAccordion** | Expandable/collapsible panels that can display multiple items with optional icons, badges, and callbacks for toggling. |
| **ReqoreBreadcrumbs** | Navigation component displaying hierarchical breadcrumb trails with responsive collapse and optional tab support. An optional `rightElement` keeps its natural width and is excluded from the trail's overflow calculation, so it can never cover the breadcrumbs: the trail is `flex: 1; min-width: 0; overflow: hidden` and collapses into the current-page dropdown instead. |
| **ReqoreButton** | Primary action button with support for icons, badges, loading states, effects, multiple style variants (minimal, flat, transparent), an optional `raised` prop that adds a subtle 3D inset highlight when paired with `flat`, and an optional `radiusSize` (`TSizes`) that decouples corner roundness from `size` using the pronounced `RADIUS_FROM_RADIUS_SIZE` scale. **Form attributes and links** (new in 0.77.4): `type`, `name`, `value`, `form`, `formAction`, `formEncType`, `formMethod`, `formNoValidate` and `formTarget` reach the `<button>`, so a button can be a named submit (the form posts the pressed button's `name=value`) or a `type='button'` that never submits. **There is no default `type`** — a `ReqoreButton` inside a `<form>` submits it, exactly as an HTML button does and as it always has; give every in-form button that must not submit `type='button'`. `href` renders the button as a real link (`<a href>`: middle-click, open in a new tab, link semantics), with `target`, `rel`, `download`, `hrefLang` and `referrerPolicy`; it looks exactly like the button (no underline), and an explicit `as` still wins. A disabled link drops its `href`, gets `aria-disabled` and is dimmed like a disabled button (`&[aria-disabled='true']` shares the `:disabled` style). **Font** (changed in 0.78.0): `font-family: inherit` — the page's font, or `theme.fontFamily` when the provider names one — where it used to be left to the browser, which draws form controls in the platform's control face (`-webkit-small-control`: system-ui on macOS, the system sans on Linux) whatever the page is set in. `effect.fontFamily` still picks a font for one control. |
| **ReqoreButtonRail** | A floating toolbar: a frosted pill surface hosting a row (or, with `vertical`, a column) of buttons — an editor's Select / Undo / Redo / History bar, a zoom control, a view switcher. Positioning is not the component's job; the caller places it (fixed, sticky, in flow). Built ON `ReqoreControlGroup`, so its buttons inherit the group's `size` / `intent` / `customTheme` / `minimal` / `fluid` / `fixed` exactly as a control group's children do (the child's own value wins; a prop neither side set stays absent, never `undefined`). On top of that the rail gives every button `flat` (the rail is their surface), `pill` while the rail is a pill, `rounded={false}` when the rail is square and `disabled` when the rail is; `buttonProps` adds more defaults of your own (e.g. `{ minimal: true }`), and a button's own props always win. Buttons come from `children` (any element: `ReqoreButton`, `ReqoreDropdown`, …; intrinsic elements are left untouched), from `items` (an array of `ReqoreButton` props — `label` is the text, `id` doubles as the React key), or both: items render first and neither form is dropped. **Surface props** (they describe the rail, not its buttons): `flat` (default `false` — a hairline border derived from the theme, tinted by `intent` when set), `transparent` (no surface colour), `minimal` (no surface and no border — and, as in a control group, minimal buttons), `raised` (the inset highlight; renders only with `flat`, per the repo-wide rule), `elevated` (default `true` — a two-layer floating lift, lighter on a light theme; never painted on a transparent / minimal rail), `opacity` (surface colour alpha, default `0.78`) and `blur` (backdrop blur in px, default `14`): below `opacity` 1 the surface is frosted glass over whatever is behind it — every colour is derived from the theme's `main`, so it works on light and dark themes alike. `intent` also tints the surface (a 16% mix into the surface colour). `rounded` (default `true`) makes it a pill — concentric with its pill buttons (half a button's height plus the padding), so a column of labelled buttons gets rounded ends that clear them instead of a `9999px` stadium that cuts into them; `radiusSize` (`TSizes`) swaps the pill for a fixed radius from the pronounced `RADIUS_FROM_RADIUS_SIZE` scale; `rounded={false}` squares the rail and its buttons. `effect` paints the surface: `gradient` (a single gradient or an array of stacked gradients; with `gradient.surface` a flowing gradient RING around the rail's own surface — the "working" state), `glow` (one glow or a list — e.g. a two-tone purple/green glow — composed with the lift shadow via the shared `withGlow` helper from `Effect`, so neither replaces the other), `backgroundBlur`, `opacity`, etc. **Layout props**: `vertical` lays the buttons out in a column that shares one width (the widest button's) so the rail reads as one control; `size` (default `normal`) scales the padding, the gap and the buttons; `gapSize` (default one step below `size`, so `normal` → `small`), `padded` (`true` \| `false` \| `'horizontal'` \| `'vertical'`, default `true`) and `paddingSize` (defaults to `size`); `fluid` (spans its container, the buttons grow to share the width) and `fixed` (never grows); `responsive` (horizontal rails only) folds the buttons that do not fit into the control group's overflow menu — the phone-width behaviour for a long rail. Plus `tooltip` (on the rail's surface; each button keeps its own), `disabled` (disables every button and sets `aria-disabled`; the surface is deliberately not dimmed, or the buttons would be dimmed twice), `customTheme` + `inheritCustomTheme` (the resolved theme — explicit, or inherited from an ancestor — is re-published to the buttons), `className` (merged, root carries `.reqore-button-rail`, the inner group `.reqore-button-rail-group`), `style`, any `div` attribute (e.g. `aria-label`, which a toolbar should have), and a forwarded `ref`. **Accessibility**: `role="toolbar"` with `aria-orientation`; the arrow keys along the rail's axis (left/right, or up/down when `vertical`) move focus between its enabled, tabbable controls and wrap at the ends, `Home` / `End` jump to the first / last — disabled buttons are skipped, keys pressed in a text input inside the rail are left to the input, and keys from a popover a button opened (a React portal) are ignored. It is not a roving-tabindex toolbar: every button stays in the Tab order, because a Reqore button honours the caller's own `tabIndex` and the rail does not override it. |
| **ReqoreCallout** | Inline message surface for inline notices, warnings, and confirmations. Supports a leading icon, optional `label` + `description` (or freeform `children`), badge (TReqoreBadge), accent strip (left/top; `accentSize` takes px or a `TSizes` name — `'normal'` = the 5px default), close button (`onClose` + `closeButtonProps`), and the standard prop set: intent (info/success/warning/danger; controls accent + border + icon colour), size, flat (border on `false`), rounded, `radiusSize` (`TSizes` — overrides the `size`-derived radius using the pronounced `RADIUS_FROM_RADIUS_SIZE` scale), fluid, fixed, transparent, raised (subtle 3D inset highlight when paired with `flat`), customTheme, tooltip, disabled, effect / labelEffect / descriptionEffect / contentEffect, `padded` (`true` \| `false` \| `'horizontal'` \| `'vertical'` — default `true`; the side adjacent to the accent strip still reserves room for it), `paddingSize` (`TSizes` — defaults to `size`), and click handlers. **`description` takes block content** (new in 0.78.5): text is drawn in a `<p>` as before, anything else (a `ReqoreP`, a list, a `ReqoreControlGroup`) in a `div` with the same typography; `children` are drawn in a `div` too. |
| **ReqoreCheckbox** | Toggle control that can render as a standard checkbox or switch component with customizable icons and text labels. **A real form control** (new in 0.77.4): every checkbox renders a visually hidden native `<input>` right before its box, so a `<form>` posts it, `Space` toggles it, a screen reader announces it (`role="checkbox"`, `"switch"` with `asSwitch`, `aria-readonly` when `readOnly`), and its `:focus-visible` ring is drawn round the box (outside it, in the text colour). The box and the switch are drawn exactly as before and are `aria-hidden`; they are no longer focusable themselves (the icon used to be a `tabIndex={0}` stop with no key handler). The `label` is a `<label for>` and the `description` is the input's `aria-describedby`. New props: `type` (`'checkbox'` default, or `'radio'`), `name`, `value` (posted when checked; the browser's `on` when not set), `required`, `defaultChecked` (an UNCONTROLLED checkbox: the box follows the native input; checkboxes only), and `inputProps` for any other input attribute (`id`, `form`, `onChange`, …). `aria-*` given to the checkbox go to the native input. **One press, one `onClick`**: a pointer click on the drawing is handed to the native input (which toggles and fires `change`) and the copy is stopped there, a key press or a label click activates the input and bubbles once — so `onClick` and any ancestor's click handler still run exactly once per press. A key press on a switch also calls `onCheckClick` / `onUncheckClick` for the side it moves to. `readOnly` still calls `onClick` (the caller owns the change) but the native input never toggles and reports no change. |
| **ReqoreCollapsibleContent** | Height-clipping "show more" disclosure for long content. Content taller than `maxCollapsedHeight` (default `300`px) is clipped behind a gradient fade with a "Show more" button; expanding shows it in full with a "Show less" button, while short content renders whole with no fade. Distinct from `ReqorePanel`/`ReqoreAccordion`, which fully hide/show a labelled section — this previews overflowing content in place. The fade is the surface: `intent` tints it (danger fades into red, success into green, etc.) and `customTheme.main` sets the base background color the gradient fades into — set it to match the parent's background for a seamless blend. Reveal/collapse buttons get a default `backgroundBlur` effect so they stay legible over the faded content. Props: `maxCollapsedHeight`, `defaultExpanded`, `revealOn` (`'always'` \| `'hover'`, default `'always'`; `'hover'` hides the button until hover/focus for an ambient look — gated on hover capability, so on touch the button stays visible, and while hidden it is `pointer-events: none` so it can never fire as an invisible target), `buttonAlign` (`'left'` \| `'center'` \| `'right'`, default `'center'`), `buttonFluid` (stretches the reveal button to the overlay width), `showMoreLabel` / `showLessLabel`, `showMoreIcon` / `showLessIcon`, `buttonProps` (forwarded to both buttons), plus the standard prop set: intent (tints the fade and buttons), size (scales the fade height and the buttons), fluid, transparent (drops the fade gradient, keeps the affordance), disabled (dims the surface, short-circuits handlers), customTheme, effect, tooltip. The `ResizeObserver`-backed measurement degrades gracefully where the API is unavailable. |
| **ReqoreCollection** | Grid/list view component for displaying arrays of items with filtering, sorting, zoom, and pagination capabilities. The search narrows in the collection's own order; `filterRanking="relevance"` opts into ranking the matches by label first, then badge, content, expanded content and `searchString`, exact before prefix before mention, taking precedence over the sort while the box has text. **Breaking in 0.76.0:** `defaultZoom` is now read with `??` rather than `||`, so `defaultZoom={0}` selects the lowest zoom (`tiny`) instead of falling through to `normal`. `0` was previously indistinguishable from "not set"; a caller who passed it meaning "default" must now pass nothing, or `sizeToZoom.normal`. **The zoom scale also gained two levels in 0.76.0** (additive, not breaking): it is generated from `SIZES` rather than hand-kept, so it now runs one level per size — `micro` (−0.5, 15%, 100px columns) through `massive` (2.5, 190%, 700px) — where it previously stopped at `tiny` (0, 30%) and `huge` (2, 160%). The zoom in / out controls therefore step two rungs further than before in each direction. Every level that already existed keeps its exact width and label, so a stored zoom still means what it meant; `clampZoom` snaps anything off-scale onto the nearest rung. The old hand-written maps held five of the seven sizes, so `micro` and `massive` converted to `undefined`, converted back to `normal`, and rendered at the normal row height — `micro` came out LARGER than `small`. |

| **ReqoreComment** | Single comment display component with optional icon/image, title, detail text, and action buttons. |
| **ReqoreCommentFeed** | Container component for displaying a vertical list of comments with customizable spacing between items. |
| **ReqoreContent** | Base content wrapper providing theme support and scroll handling for page content areas. |
| **ReqoreControlGroup** | Flexible group component for organizing child elements with support for stacking, spacing, responsiveness, and overflow handling. It clones each child with the group's own `minimal` / `flat` / `fixed` / `fluid` / `fill` / `size` / `intent` / `customTheme` / `stack`, resolved as "the child's value, else the group's" — so a row of controls reads as one row. **A prop neither side set is omitted, not passed as `undefined`.** That distinction is invisible for a plain Reqore child (they read their own props with their own defaults, where absent and undefined are the same), and load-bearing for a consumer's wrapper component: those typically write a default and then spread the props they were handed onto the element underneath, so an injected `undefined` would land after the default and destroy it — rendering solid in a row of minimal buttons, unfixable from the call site. If you are writing such a wrapper, still prefer a destructuring default (`({ minimal = true, ...rest })`) over a JSX default before the spread; it is the form that cannot be clobbered. |
| **ReqoreControlGroupItem** | A neutral slot that makes several elements count as ONE child of a `ReqoreControlGroup`. A control group sizes each child individually and React fragments are transparent in the DOM, so a component rendering `<>…</>` into a group silently becomes N competing flex items — and where the leading element is full-width and cannot shrink, the rest are pushed outside the container. Wrapping them in this item restores the intent. It is deliberately NOT a nested control group: it adds **no gap by default** (pass `gapSize` to opt in), because standing in for a single child means it must not inject spacing the wrapped elements did not already have. Props: `horizontal` (lay its own children in a row instead of a column), `gapSize` (`TSizes`), `fluid` / `fixed` (mirror the group's own child sizing, so the slot occupies exactly the space the child it replaces would have), plus `size`. The group's cloned child props (`minimal`, `flat`, `fill`, `stack`, `spaceBetween`, `intent`, `customTheme`) are accepted so the item is a valid group child and dropped before the DOM, but intentionally do **not** cascade to its children — re-applying them is exactly what would stop it standing in transparently. `min-width: 0` so an over-wide child shrinks instead of overflowing. |
| **ReqoreDatePicker** | Date and time picker with calendar interface, time selection, and support for various date formats and granularity options. |
| **ReqoreDataView** | Type-aware, collapsible renderer for structured records, arrays, and scalar values. Keys and compact scalar chips use consistent monospace data styling; multiline strings preserve whitespace in bounded, scrollable data blocks so large text payloads remain readable. Supports typed envelopes, embedded-data parsing, inline scalar arrays, item interaction, and controlled editing. **Font** (0.78.0): the monospace is for the data only. A value cell sets its keys and values in `MONO_FONT`, but the controls inside it — the `+ Add property` / `+ Add item` buttons, the type picker, the delete button and the edit and rename inputs of every nested level — are not in it, although buttons and inputs now take the font around them (see ReqoreButton). They are in the theme's font (`theme.fontFamily`) when the theme names one, and otherwise in the browser's own control font (`font-family: revert`), as before 0.78.0: CSS cannot name the page's font from inside a cell that has replaced it. The data itself renders exactly as before. |
| **ReqoreDescriptionList** | Read-only `<dl>`-style key/value list rendered inside a `ReqorePanel`. Built for "operator reads four labelled values top-to-bottom" surfaces (drawer lifecycle blocks, metadata strips) — distinct from `ReqoreKeyValueTable`, which is the searchable / sortable / exportable `ReqoreTable`-backed alternative. Accepts `items: { key, label?, content, intent?, uppercaseLabel? }[]`, `labelWidth`, `uppercaseLabels` (default `true` — labels read as eyebrow chips), `separatorOpacity` (default `0.06`), plus the full `IReqorePanelProps` surface forwarded to the wrapping panel: `label`, `icon`, `badge`, `flat`, `raised`, `minimal`, `rounded`, `transparent`, `intent`, `size`, `customTheme`, `effect`, `contentEffect`, `tooltip`, `disabled`. Every row reserves a 12px left intent-strip gutter so rows stay flush-aligned whether or not they carry an intent. Pass `transparent flat` (or `minimal flat`) when nesting inside an already-padded surface. |
| **ReqoreDrawer** | Sliding panel that can be positioned on any edge of the screen, with support for resizing, hiding, and optional backdrop. Resizing has a floor: an edge drawer cannot be dragged below `minSize` (default `DRAWER_MIN_SIZE`, 150px) on the axis it drags, and a modal — which drags on both — cannot go below `minWidth` / `minHeight`, falling back to `minSize` and then to `MODAL_MIN_WIDTH` x `MODAL_MIN_HEIGHT` (200x80, the size at which the panel's own title and close control are still in the box with a readable line beneath them). Declare `minWidth` / `minHeight` when the CONTENT needs more than the chrome does. **The floor applies AT REST, not only to dragging** — `re-resizable` takes these both as its drag clamp and as the element's inline `min-width` / `min-height`, so a modal smaller than the floor is grown to it with nobody touching it. Width is inert in practice (the default is `80vw`), so what this changes is a modal with under 80px of content — in practice one with no header, which now reserves room for chrome it does not have. Pass a smaller `minHeight` where that matters; it overrides the default floor at any value. All three floors take **`px`, `%`, `vw` or `vh` and nothing else**: the value is read twice, by `re-resizable`'s `getPixelSize()` for the drag clamp and as the element's inline CSS min, and the two disagree everywhere outside those four units — `'20rem'` / `'50vmin'` are valid CSS but `NaN` in the clamp (so the box LOOKS floored and the drag is not), a bare `'200'` is the reverse. The props are typed `string`, so neither is a type error. The box is NOT clipped when it is `resizable` (the default) or `hidable`, because both put something outside it: `re-resizable` centres every handle ON the edge it drags (sides are 10px bands hung at -5px, corners 20x20 squares hung at -10px on both axes), so a clip amputates whatever hangs outside and leaves a corner as a 10x10 target buried inside the dialog with the corner itself belonging to the backdrop — which dismisses it. Unclipped, a corner is grabbable from up to 10px outside the box and resizes both axes at once, still stopping at the floor. A drawer that is neither resizable nor hidable draws nothing outside itself and keeps its clip. Content clipping is the panel's own either way, which it drops only when a sticky header has to escape. **Breaking in 0.76.0:** the handles sit ABOVE the backdrop, so a resizable drawer or modal — the default — has a band along its outside where a backdrop click no longer dismisses it: ~5px down each side and ~10px at each corner, which is the same geometry that makes the corners grabbable and cannot be had without it. Pass `resizable={false}` where dismissal matters more than dragging. `resizable={false}` now reaches a MODAL too: it draws no handles at all, where before every direction was enabled for a modal regardless and a drag moved the box and then snapped back. |
| **ReqoreDropdown** | Button-triggered dropdown menu supporting filtering, nested items, multi-select, and keyboard navigation. `filterRanking="relevance"` opts the filter into ranking matches by label, then value, description and children, exact before prefix before mention (dividers are dropped while ranking). Its forwarded ref resolves to the rendered trigger element, allowing form engines to focus or measure the actual control without React ref warnings. `scrollToSelected` centres the selected item vertically on open; the scroll is smooth unless `animations.popovers` is `false` or the OS prefers reduced motion, in which case it jumps straight there (which is also what makes it deterministic for snapshot tests). **Breaking in 0.76.0:** an option marked `readOnly` can no longer be chosen. Before this it was fully selectable by click and by keyboard, so a caller who used `readOnly` only to mark a row as not-currently-actionable now finds it inert, with no type change to warn them. **An option that cannot be chosen but must stay readable is `readOnly`, not `disabled`.** `disabled` renders a row `pointer-events: none`, which takes its tooltip and its row actions with it — so disabling an option destroys any explanation of why it is unavailable. `readOnly` keeps the row at full opacity with its pointer events intact and only marks it `cursor: not-allowed`; the list then refuses to select it, by click and by keyboard, and the reason can live in its `description`, `tooltip`, `badge`, `intent` or a pressable `rightAction`. A read-only row that has a SUBMENU is still walked and opened, because entering a submenu is navigation rather than a choice. |
| **ReqoreEffect** | Styled component providing visual effects like gradients, glows, filters, and text decorations. `effect.gradient` accepts either a single gradient object or an array of gradient objects — when an array is provided each entry is stacked as a CSS `background-image` layer in order (first entry on top); border-image / readable-text / animation behaviour is driven by the first gradient. Each gradient supports an optional radial `size` hint (e.g. `'ellipse 90% 120%'` or CSS sizing keywords) that is rendered between the shape and the position. Because `effect.gradient` may be a single object **or** an array, code that reads a gradient's config back out must not reach into `effect.gradient.colors` directly (it is `undefined` when an array was passed) — use the exported `getPrimaryGradient(effect.gradient)` for the top layer (or `normalizeGradients(effect.gradient)` for all layers). `gradient.surface` (a colour, alpha allowed) turns the FIRST gradient into a ring: the gradient paints only the border box and the surface is filled with that colour (a padding-box layer), the readable text colour follows the surface, and `animate` flows the ring — the "AI is working" border; it needs a border to draw on (inert on text, on a `flat` surface and when `borderColor` is set). `effect.glow` accepts a single glow OR a list, painted together (first on top), and each glow takes an `x` / `y` offset in px: two offset glows make a two-tone shadow. The list's trigger is the first glow's `when`, and a text glow paints only the first; code that reads a glow back must use the exported `getPrimaryGlow` / `normalizeGlows` rather than `effect.glow.color`. `size` 0 keeps its historical meaning (the default 2px spread). `effect.borderStyle` (`'solid'` \| `'dashed'` \| `'dotted'`) sets how a border is drawn on ANY effect-aware surface — a button, a tag, a panel, a callout, an entity row. A dashed or dotted border is the convention for an *add* affordance, where the control stands in for content that does not exist yet. Applied with `!important`, like `borderColor` and `fontFamily`, because components declare their border with the `border` SHORTHAND (`1px solid …`) which resets `border-style`. It sets the style only and never draws a border that was not there, so it is inert on a `flat` surface rather than wrong. |

| **ReqoreFadeScroller** | Single-line horizontal scroller that fades whichever edge still has content out of view — for chip strips, tag rows, stat rails and any row of peers that would otherwise wrap into a ragged block on a narrow screen. Reach for this instead of `ReqoreControlGroup wrap` whenever wrapping would turn one row into N rows on a phone and push the page's real content below the fold; the fade is what makes the overflow discoverable, since a clipped row otherwise looks like a complete one. The gradients are overlay pseudo-elements on the wrapper (not inside the scrolling box, where they would scroll away) and are `pointer-events: none`, so they never swallow a click on the item beneath. The native scrollbar is hidden on purpose — it is thicker than a row of chips — and the row stays scrollable by wheel, trackpad, touch and keyboard. Props: `gapSize` (`TSizes`, default `normal`), `verticalAlign` (`'flex-start'` \| `'center'` \| `'flex-end'` \| `'stretch'`, default `'center'`), `rigid` (default `true` — children keep their natural width and overflow rather than squashing; pass `false` for a rail of self-sizing grow-tiles whose own `flex` should win), `fadeColor` (defaults to the resolved main background so the fade reads as a dissolve rather than a grey smudge), `fade` (default `true`), `dragToScroll` (default `false` — grab the row and pull it sideways; a mouse has no horizontal axis, so an overflowing row is otherwise reachable only by shift+wheel or a trackpad gesture. ## Props and the DOM (0.78.5)

Reqore styles its components with props, and none of those props is written onto an element:

- **A prop name that is also an HTML attribute reaches only the elements it is an attribute of.** `size='small'`, `checked`, `selected`, `disabled`, `readOnly`, `placeholder`, `width`, `wrap`, `color`, `type`, `value`, … are Reqore props on most components. A `div` or `span` no longer receives them as attributes (`size="normal"` was written onto most of Reqore's elements), while an `input` still gets its `size`, `readOnly` and `placeholder`, and a `button` its `disabled`. Reqore's own `styled` (`src/helpers/styled.ts`) applies this to every styled component, and an ESLint rule keeps Reqore's sources on it.
- **A component rendered `as` another component receives only its own props.** `<ReqoreButton as={Link} to='/x' fluid compact />` hands the link `to`, `children`, `className`, event handlers, `aria-*` / `data-*` and the HTML attributes of a button or link, never `fluid`, `compact`, `flat`, `maxWidth`, `tooltip` or the stack-position flags a `ReqoreControlGroup` clones onto its children. The same holds for `ReqoreTag`, `ReqorePanel` (a resizable panel still hands re-resizable its `size`, `enable`, `minWidth`, …), `ReqoreTextarea` (Slate's editable keeps `renderElement`, `renderLeaf`, `decorate`), `ReqoreP`, the tabs list item, the icon's wrapper, and the callout, entity-row, severity-row, feature-card and testimonial surfaces.
- **Attributes that left the DOM.** None of these changes what is drawn: `disabled` on a panel's `div`, a tag's `span`, a tab's wrapper and a timeline's `li` (which now says `aria-disabled`); `readonly` on a read-only or loading `ReqoreButton`; `size` on every `div` and `span`.
- **A component rendered `as` another DOM tag keeps that tag's state attributes.** The lists of styling props are built against each component's default element. Given `as` an element that has `disabled`, `readOnly`, `checked` or `selected`, the attribute is that element's: `<ReqorePanel as='fieldset' disabled>` disables its fields, and `<ReqoreTag as='button' disabled>` is a disabled button.
