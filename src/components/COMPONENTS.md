# ReQore Components

| Component | Description |
| --- | --- |
| **ReqoreAccordion** | Expandable/collapsible panels that can display multiple items with optional icons, badges, and callbacks for toggling. |
| **ReqoreBreadcrumbs** | Navigation component displaying hierarchical breadcrumb trails with responsive collapse and optional tab support. An optional `rightElement` keeps its natural width and is excluded from the trail's overflow calculation, so it can never cover the breadcrumbs: the trail is `flex: 1; min-width: 0; overflow: hidden` and collapses into the current-page dropdown instead. |
| **ReqoreButton** | Primary action button with support for icons, badges, loading states, effects, multiple style variants (minimal, flat, transparent), an optional `raised` prop that adds a subtle 3D inset highlight when paired with `flat`, and an optional `radiusSize` (`TSizes`) that decouples corner roundness from `size` using the pronounced `RADIUS_FROM_RADIUS_SIZE` scale. |
| **ReqoreCallout** | Inline message surface for inline notices, warnings, and confirmations. Supports a leading icon, optional `label` + `description` (or freeform `children`), badge (TReqoreBadge), accent strip (left/top; `accentSize` takes px or a `TSizes` name — `'normal'` = the 5px default), close button (`onClose` + `closeButtonProps`), and the standard prop set: intent (info/success/warning/danger; controls accent + border + icon colour), size, flat (border on `false`), rounded, `radiusSize` (`TSizes` — overrides the `size`-derived radius using the pronounced `RADIUS_FROM_RADIUS_SIZE` scale), fluid, fixed, transparent, raised (subtle 3D inset highlight when paired with `flat`), customTheme, tooltip, disabled, effect / labelEffect / descriptionEffect / contentEffect, `padded` (`true` \| `false` \| `'horizontal'` \| `'vertical'` — default `true`; the side adjacent to the accent strip still reserves room for it), `paddingSize` (`TSizes` — defaults to `size`), and click handlers. |
| **ReqoreCheckbox** | Toggle control that can render as a standard checkbox or switch component with customizable icons and text labels. |
| **ReqoreCollapsibleContent** | Height-clipping "show more" disclosure for long content. Content taller than `maxCollapsedHeight` (default `300`px) is clipped behind a gradient fade with a "Show more" button; expanding shows it in full with a "Show less" button, while short content renders whole with no fade. Distinct from `ReqorePanel`/`ReqoreAccordion`, which fully hide/show a labelled section — this previews overflowing content in place. The fade is the surface: `intent` tints it (danger fades into red, success into green, etc.) and `customTheme.main` sets the base background color the gradient fades into — set it to match the parent's background for a seamless blend. Reveal/collapse buttons get a default `backgroundBlur` effect so they stay legible over the faded content. Props: `maxCollapsedHeight`, `defaultExpanded`, `revealOn` (`'always'` \| `'hover'`, default `'always'`; `'hover'` hides the button until hover/focus for an ambient look — gated on hover capability, so on touch the button stays visible, and while hidden it is `pointer-events: none` so it can never fire as an invisible target), `buttonAlign` (`'left'` \| `'center'` \| `'right'`, default `'center'`), `buttonFluid` (stretches the reveal button to the overlay width), `showMoreLabel` / `showLessLabel`, `showMoreIcon` / `showLessIcon`, `buttonProps` (forwarded to both buttons), plus the standard prop set: intent (tints the fade and buttons), size (scales the fade height and the buttons), fluid, transparent (drops the fade gradient, keeps the affordance), disabled (dims the surface, short-circuits handlers), customTheme, effect, tooltip. The `ResizeObserver`-backed measurement degrades gracefully where the API is unavailable. |
| **ReqoreCollection** | Grid/list view component for displaying arrays of items with filtering, sorting, zoom, and pagination capabilities. The search narrows in the collection's own order; `filterRanking="relevance"` opts into ranking the matches by label first, then badge, content, expanded content and `searchString`, exact before prefix before mention, taking precedence over the sort while the box has text. **Breaking in 0.76.0:** `defaultZoom` is now read with `??` rather than `||`, so `defaultZoom={0}` selects the lowest zoom (`tiny`) instead of falling through to `normal`. `0` was previously indistinguishable from "not set"; a caller who passed it meaning "default" must now pass nothing, or `sizeToZoom.normal`. **The zoom scale also gained two levels in 0.76.0** (additive, not breaking): it is generated from `SIZES` rather than hand-kept, so it now runs one level per size — `micro` (−0.5, 15%, 100px columns) through `massive` (2.5, 190%, 700px) — where it previously stopped at `tiny` (0, 30%) and `huge` (2, 160%). The zoom in / out controls therefore step two rungs further than before in each direction. Every level that already existed keeps its exact width and label, so a stored zoom still means what it meant; `clampZoom` snaps anything off-scale onto the nearest rung. The old hand-written maps held five of the seven sizes, so `micro` and `massive` converted to `undefined`, converted back to `normal`, and rendered at the normal row height — `micro` came out LARGER than `small`. |
| **ReqoreColumns** | Layout component using CSS Grid to arrange content into responsive columns with customizable gaps and alignment. |
| **ReqoreComment** | Single comment display component with optional icon/image, title, detail text, and action buttons. |
| **ReqoreCommentFeed** | Container component for displaying a vertical list of comments with customizable spacing between items. |
| **ReqoreContent** | Base content wrapper providing theme support and scroll handling for page content areas. |
| **ReqoreControlGroup** | Flexible group component for organizing child elements with support for stacking, spacing, responsiveness, and overflow handling. It clones each child with the group's own `minimal` / `flat` / `fixed` / `fluid` / `fill` / `size` / `intent` / `customTheme` / `stack`, resolved as "the child's value, else the group's" — so a row of controls reads as one row. **A prop neither side set is omitted, not passed as `undefined`.** That distinction is invisible for a plain Reqore child (they read their own props with their own defaults, where absent and undefined are the same), and load-bearing for a consumer's wrapper component: those typically write a default and then spread the props they were handed onto the element underneath, so an injected `undefined` would land after the default and destroy it — rendering solid in a row of minimal buttons, unfixable from the call site. If you are writing such a wrapper, still prefer a destructuring default (`({ minimal = true, ...rest })`) over a JSX default before the spread; it is the form that cannot be clobbered. |
| **ReqoreControlGroupItem** | A neutral slot that makes several elements count as ONE child of a `ReqoreControlGroup`. A control group sizes each child individually and React fragments are transparent in the DOM, so a component rendering `<>…</>` into a group silently becomes N competing flex items — and where the leading element is full-width and cannot shrink, the rest are pushed outside the container. Wrapping them in this item restores the intent. It is deliberately NOT a nested control group: it adds **no gap by default** (pass `gapSize` to opt in), because standing in for a single child means it must not inject spacing the wrapped elements did not already have. Props: `horizontal` (lay its own children in a row instead of a column), `gapSize` (`TSizes`), `fluid` / `fixed` (mirror the group's own child sizing, so the slot occupies exactly the space the child it replaces would have), plus `size`. The group's cloned child props (`minimal`, `flat`, `fill`, `stack`, `spaceBetween`, `intent`, `customTheme`) are accepted so the item is a valid group child and dropped before the DOM, but intentionally do **not** cascade to its children — re-applying them is exactly what would stop it standing in transparently. `min-width: 0` so an over-wide child shrinks instead of overflowing. |
| **ReqoreDatePicker** | Date and time picker with calendar interface, time selection, and support for various date formats and granularity options. |
| **ReqoreDataView** | Type-aware, collapsible renderer for structured records, arrays, and scalar values. Keys and compact scalar chips use consistent monospace data styling; multiline strings preserve whitespace in bounded, scrollable data blocks so large text payloads remain readable. Supports typed envelopes, embedded-data parsing, inline scalar arrays, item interaction, and controlled editing. |
| **ReqoreDescriptionList** | Read-only `<dl>`-style key/value list rendered inside a `ReqorePanel`. Built for "operator reads four labelled values top-to-bottom" surfaces (drawer lifecycle blocks, metadata strips) — distinct from `ReqoreKeyValueTable`, which is the searchable / sortable / exportable `ReqoreTable`-backed alternative. Accepts `items: { key, label?, content, intent?, uppercaseLabel? }[]`, `labelWidth`, `uppercaseLabels` (default `true` — labels read as eyebrow chips), `separatorOpacity` (default `0.06`), plus the full `IReqorePanelProps` surface forwarded to the wrapping panel: `label`, `icon`, `badge`, `flat`, `raised`, `minimal`, `rounded`, `transparent`, `intent`, `size`, `customTheme`, `effect`, `contentEffect`, `tooltip`, `disabled`. Every row reserves a 12px left intent-strip gutter so rows stay flush-aligned whether or not they carry an intent. Pass `transparent flat` (or `minimal flat`) when nesting inside an already-padded surface. |
| **ReqoreDrawer** | Sliding panel that can be positioned on any edge of the screen, with support for resizing, hiding, and optional backdrop. Resizing has a floor: an edge drawer cannot be dragged below `minSize` (default `DRAWER_MIN_SIZE`, 150px) on the axis it drags, and a modal — which drags on both — cannot go below `minWidth` / `minHeight`, falling back to `minSize` and then to `MODAL_MIN_WIDTH` x `MODAL_MIN_HEIGHT` (200x80, the size at which the panel's own title and close control are still in the box with a readable line beneath them). Declare `minWidth` / `minHeight` when the CONTENT needs more than the chrome does. All three floors take **`px`, `%`, `vw` or `vh` and nothing else**: the value is read twice, by `re-resizable`'s `getPixelSize()` for the drag clamp and as the element's inline CSS min, and the two disagree everywhere outside those four units — `'20rem'` / `'50vmin'` are valid CSS but `NaN` in the clamp (so the box LOOKS floored and the drag is not), a bare `'200'` is the reverse. The props are typed `string`, so neither is a type error. The box is NOT clipped when it is `resizable` (the default) or `hidable`, because both put something outside it: `re-resizable` centres every handle ON the edge it drags (sides are 10px bands hung at -5px, corners 20x20 squares hung at -10px on both axes), so a clip amputates whatever hangs outside and leaves a corner as a 10x10 target buried inside the dialog with the corner itself belonging to the backdrop — which dismisses it. Unclipped, a corner is grabbable from up to 10px outside the box and resizes both axes at once, still stopping at the floor. A drawer that is neither resizable nor hidable draws nothing outside itself and keeps its clip. Content clipping is the panel's own either way, which it drops only when a sticky header has to escape. **Breaking in 0.76.0:** the handles sit ABOVE the backdrop, so a resizable drawer or modal — the default — has a band along its outside where a backdrop click no longer dismisses it: ~5px down each side and ~10px at each corner, which is the same geometry that makes the corners grabbable and cannot be had without it. Pass `resizable={false}` where dismissal matters more than dragging. `resizable={false}` now reaches a MODAL too: it draws no handles at all, where before every direction was enabled for a modal regardless and a drag moved the box and then snapped back. |
| **ReqoreDropdown** | Button-triggered dropdown menu supporting filtering, nested items, multi-select, and keyboard navigation. `filterRanking="relevance"` opts the filter into ranking matches by label, then value, description and children, exact before prefix before mention (dividers are dropped while ranking). Its forwarded ref resolves to the rendered trigger element, allowing form engines to focus or measure the actual control without React ref warnings. `scrollToSelected` centres the selected item vertically on open; the scroll is smooth unless `animations.popovers` is `false` or the OS prefers reduced motion, in which case it jumps straight there (which is also what makes it deterministic for snapshot tests). **Breaking in 0.76.0:** an option marked `readOnly` can no longer be chosen. Before this it was fully selectable by click and by keyboard, so a caller who used `readOnly` only to mark a row as not-currently-actionable now finds it inert, with no type change to warn them. **An option that cannot be chosen but must stay readable is `readOnly`, not `disabled`.** `disabled` renders a row `pointer-events: none`, which takes its tooltip and its row actions with it — so disabling an option destroys any explanation of why it is unavailable. `readOnly` keeps the row at full opacity with its pointer events intact and only marks it `cursor: not-allowed`; the list then refuses to select it, by click and by keyboard, and the reason can live in its `description`, `tooltip`, `badge`, `intent` or a pressable `rightAction`. A read-only row that has a SUBMENU is still walked and opened, because entering a submenu is navigation rather than a choice. |
| **ReqoreEffect** | Styled component providing visual effects like gradients, glows, filters, and text decorations. `effect.gradient` accepts either a single gradient object or an array of gradient objects — when an array is provided each entry is stacked as a CSS `background-image` layer in order (first entry on top); border-image / readable-text / animation behaviour is driven by the first gradient. Each gradient supports an optional radial `size` hint (e.g. `'ellipse 90% 120%'` or CSS sizing keywords) that is rendered between the shape and the position. Because `effect.gradient` may be a single object **or** an array, code that reads a gradient's config back out must not reach into `effect.gradient.colors` directly (it is `undefined` when an array was passed) — use the exported `getPrimaryGradient(effect.gradient)` for the top layer (or `normalizeGradients(effect.gradient)` for all layers). `effect.borderStyle` (`'solid'` \| `'dashed'` \| `'dotted'`) sets how a border is drawn on ANY effect-aware surface — a button, a tag, a panel, a callout, an entity row. A dashed or dotted border is the convention for an *add* affordance, where the control stands in for content that does not exist yet. Applied with `!important`, like `borderColor` and `fontFamily`, because components declare their border with the `border` SHORTHAND (`1px solid …`) which resets `border-style`. It sets the style only and never draws a border that was not there, so it is inert on a `flat` surface rather than wrong. |

Accepts an optional `radiusSize` (`TSizes`) that is forwarded to the underlying panel and uses the pronounced `RADIUS_FROM_RADIUS_SIZE` scale. |

Supports the standard prop set: intent (with tinted backgrounds), size, flat (border on `false`), rounded, fluid, transparent, raised (subtle 3D inset highlight when paired with `flat`), customTheme, tooltip, disabled, effect / labelEffect / descriptionEffect / metadataEffect, wrap (single-line ellipsis on `false`), `iconHasBackground` (defaults to `true` on opaque rows and `false` when `transparent={true}` so the tile does not fight the transparent surface; pass an explicit boolean to override), `padded` (`true` \| `false` \| `'horizontal'` \| `'vertical'` — default `true`; controls which axes receive outer padding), `paddingSize` (`TSizes` — defaults to `size`; scales padding independently from text/icon scale), and click handlers. **Row actions do not bubble into the row's own `onClick`** — every action button and overflow menu stops propagation, so an action and the row never both fire; an action that *should* also trigger the row calls the row's handler itself. | **ReqoreFadeScroller** | Single-line horizontal scroller that fades whichever edge still has content out of view — for chip strips, tag rows, stat rails and any row of peers that would otherwise wrap into a ragged block on a narrow screen. Reach for this instead of `ReqoreControlGroup wrap` whenever wrapping would turn one row into N rows on a phone and push the page's real content below the fold; the fade is what makes the overflow discoverable, since a clipped row otherwise looks like a complete one. The gradients are overlay pseudo-elements on the wrapper (not inside the scrolling box, where they would scroll away) and are `pointer-events: none`, so they never swallow a click on the item beneath. The native scrollbar is hidden on purpose — it is thicker than a row of chips — and the row stays scrollable by wheel, trackpad, touch and keyboard. Props: `gapSize` (`TSizes`, default `normal`), `verticalAlign` (`'flex-start'` \| `'center'` \| `'flex-end'` \| `'stretch'`, default `'center'`), `rigid` (default `true` — children keep their natural width and overflow rather than squashing; pass `false` for a rail of self-sizing grow-tiles whose own `flex` should win), `fadeColor` (defaults to the resolved main background so the fade reads as a dissolve rather than a grey smudge), `fade` (default `true`), `dragToScroll` (default `false` — grab the row and pull it sideways; a mouse has no horizontal axis, so an overflowing row is otherwise reachable only by shift+wheel or a trackpad gesture. A drag that actually moved the row swallows the click that follows it, so pulling past a clickable child does not activate it while a plain click still does; text inputs are excluded as drag origins. The `grab` cursor appears only while the row overflows, via a `reqore-fade-scroller-draggable` class toggled by the same measurement that drives the fades — drag state is carried by classes, not React state, so a drag never re-renders the row's children), plus `fluid` (default `true`; pass `false` when the row sits beside other content in a flex layout and should take only the width it needs), `intent` and `customTheme`. Edge state is recomputed on scroll, on resize (`ResizeObserver`, degrading gracefully where unavailable) and after every render, since children can change width without the scroller resizing. |

| **ReqorePanel** | Container component with optional header, footer, actions, and resizable panels with breadcrumbs support. Optional `raised` adds a subtle 3D inset highlight when paired with `flat`, suppressed whenever the panel actually draws a border — normally that means an `intent` is set, but an `accentPosition` panel draws no border, so `raised` applies there too. Optional `accentPosition` (`'left'` \| `'top'`) + `accentSize` (px or a `TSizes` name via `ACCENT_SIZE_TO_PX`; default `5` = `'normal'`) render the intent as a single edge strip instead of tinting the whole border (the border goes neutral — at rest AND on hover — or disappears on `flat` panels) — mirroring ReqoreCallout's accent API.
